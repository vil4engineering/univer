Лента роликов на iOS: опыт работы с AVPlayer


❓ Почему стандартный AVPlayer плохо подходит для ленты коротких видео? Ответ как раз в этой статье.

🔴 Главная проблема - долгий старт на слабых сетях и конкуренция за канал между несколькими плеерами, из‑за чего активный ролик медленнее набирает буфер. Решение - уменьшить агрессивную предзагрузку у неактивных плееров (preferredForwardBufferDuration), запускать предзагрузку следующего ролика только после readyToPlay активного, убрать третий «предыдущий» плеер и переиспользовать его. Это позволило улучшить хвосты распределения: p90/p99 времени готовности сократились примерно на 12%, частота ребуферингов упала с 1.6% до 0.25%

⚠️ Практические ограничения AVPlayer, которые побудили писать собственный плеер: 
➡️ нельзя жёстко контролировать момент старта (automaticallyWaitsToMinimizeStalling)
➡️ нет точного API для управления буфером и выбором конкретного варианта качества из HLS-плейлиста
➡️ невозможно легко исключить аудиодорожку при выключенном звуке для экономии трафика (muxed HLS)
➡️ встроенный кэш и офлайн API не дают нужного контроля, а при ошибках AVPlayer очищает слой и теряются уже загруженные данные

✔️ Итог - AVPlayer годится для обычных задач, но для ленты коротких роликов авторы перешли к собственному решению на MPEG‑DASH, чтобы получить полный контроль над буферизацией, кэшем и качеством воспроизведения.

## Keys

- `preferredForwardBufferDuration` for inactive players
- Preload next only after active `readyToPlay`
- Avoid three-way competing downloads
