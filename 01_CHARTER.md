# 01 · Charter

**Project:** Engineering University  
**Status:** Phase 1 governance  
**Related:** [PROJECT_STATUS.md](PROJECT_STATUS.md) · [02_PHILOSOPHY.md](02_PHILOSOPHY.md)

## Mission

Build a living engineering university: a long-term system where engineering knowledge is learned, verified, practiced, reused, taught, and preserved through real software and harder problems over time.

The name may change. The idea must not.

## What this is

Engineering University is an educational system with:

- Faculties
- A curriculum (program of study)
- Learning paths for different students
- Laboratories that answer one engineering question
- Subjects that end in Interview Readiness
- Eventually, one Living Application chosen for educational value

It is **not** a wiki, bookmark archive, cheat sheet, or folder tour of APIs.

## What this is not

Do not turn this repository into:

- a note collection
- a Notion clone
- a document dump
- a directory of isolated demos
- an interview memorization pack
- product ownership of sibling apps
- a career presentation system

## Students

One university. Two primary students. Shared system.

### Student A — Experienced engineer

Already works professionally.

Needs:

- architecture and systems judgment
- modern mobile engineering
- AI-native engineering skill
- product thinking
- interview-grade explainability
- continuous growth that survives technology change

### Student B — Developing engineer (son)

Needs:

- fundamentals
- programming
- mathematical and algorithmic thinking
- problem solving
- gradual progression
- confidence through building

The university must support both without becoming two disconnected projects.

## Primary goals

- Become a stronger senior engineer
- Become an AI-native engineer without replacing understanding with tools
- Learn continuously as technologies change
- Prepare for interviews through genuine understanding
- Build engineering intuition
- Preserve knowledge in reusable form
- Teach another person
- Remain useful for 5–10 years

## Binding principles (summary)

Full treatment: [02_PHILOSOPHY.md](02_PHILOSOPHY.md).

1. **Completeness:** Knowledge is only considered complete when it can be explained, demonstrated, tested, and reused.
2. **Progression:** Engineering is learned through progressively solving harder real problems.
3. **Problem-first:** Problem → Need → Concept → Implementation → Reflection.
4. **Learn by building:** Important concepts must eventually exist as working software.
5. **Architecture and mental models before APIs.**
6. **Explainability:** If it cannot be explained simply, it is not yet understood.
7. **AI as accelerator, never as substitute for engineering.**

## Organization

Academic organization uses **Faculties** and a **Curriculum**.

Physical folders on disk are storage. Students study a program — not a Git tree.

See [03_CURRICULUM.md](03_CURRICULUM.md) and [04_STRUCTURE.md](04_STRUCTURE.md).

## Naming rule

In university governance and future public framing, use **Engineering University**.

Do not describe this project as a "knowledge base."

## Success over a decade

The university succeeds if:

- Student A keeps growing through harder problems and reusable systems
- Student B can progress from foundations to real building
- Subjects remain completable under the Completeness Principle
- Laboratories stay small and purposeful
- One Living Application (when chosen) stays coherent
- Technology churn does not force a total rewrite of the educational system

## Anti-success

The project fails if it becomes a searchable pile of notes that nobody practices, tests, or teaches.
