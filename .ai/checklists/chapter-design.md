# Checklist: Chapter design

Use before approving Phase B write. Design file: `…/DESIGN.md`.

## Contract

- [ ] Fundamental **why** present (not only “what is X?”)
- [ ] North-star thought / Hero promise clear
- [ ] Anti-goal stated (what the chapter must not become)
- [ ] Topic id / faculty / path hooks proposed
- [ ] Starts from problem / story — no definition-first plan

## Shape

- [ ] Sections cover chapter-shape spine (Интуиция … Рефлексия) or honest deferrals
- [ ] History is a narrative arc, not a date dump
- [ ] At least one concrete example plan (or multi-form example)
- [ ] Production / failure or engineering-cycle angle present
- [ ] Interview projection: questions + follow-ups + mistakes (no second encyclopedia)
- [ ] Practice includes non-code exercise when topic allows
- [ ] Next / graph links listed
- [ ] Closing mental-model reflection planned

## Media

- [ ] Each proposed diagram has an explicit teaching purpose
- [ ] Illustrations are briefs with “why”, not decoration
- [ ] Callout types sketched

## Quality gate

- [ ] Interesting to a 10-year engineer, not only a beginner
- [ ] Survives API churn (idea-level spine)
- [ ] Matches content-philosophy + language policy
- [ ] Write plan for Author is actionable
- [ ] Owner/Reviewer explicit **Approve design** before write-chapter

## Reject if

- Design is already a full essay pretending to be a design
- Tech catalog spine (Swift→syntax list, iOS→framework list)
- No why-question
- Diagrams without meaning
