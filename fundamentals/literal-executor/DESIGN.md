## Passport (контракт)

1. **What:** компьютер как **универсальный буквальный исполнитель** (не «умная коробка»).  
2. **Problem:** задачи разные; железо одно; нельзя пересобирать машину под каждую профессию.  
3. **Why:** нужна машина, которая **ничего не домысливает**, но исполняет **любую** точно записанную инструкцию.  
4. **Before (гл. 0):** нужны программы = точные инструкции для буквального помощника (метафора).  
5. **Gap после 0:** ещё не ясно, *почему железо такое* — универсальное и «тупое», а не «понимающее».  
6. **Modern:** один CPU / устройство; смена задачи = смена **программы**, не железа.  
7. **Next:** Binary → Machine Code → Compiler (почему инструкции обязаны быть в двух состояниях и как текст доходит до цикла).  
8. **Where used:** весь Spine; мост к iOS («странный» UI = дырка в инструкции).

**Fundamental why (один):**  
Почему нам нужна машина, которая ничего не домысливает — а не «умный» помощник, который угадывает намерение?

**H1:** Почему нам нужен буквальный исполнитель?

**Deck (1 строка):**  
Компьютер — не «умная коробка». Это универсальный исполнитель: смена профессии = смена программы.

**Анти-цели:**

- не пересказывать аксиому гл. 0 целиком  
- не урок Binary / транзисторов / ISA  
- не история AI («почему не сразу нейросеть»)  
- не справочник Fetch-Decode-Execute на 3 экрана

## Сдвиг относительно главы 0

| Гл. 0 | Гл. 1 |
|-------|--------|
| Зачем нужны **программы** | Зачем такой тип **машины** |
| Помощник-метафора | Тот же помощник → **один ящик, много профессий** |
| «Не додумывает» = аксиома | «Не додумывает» = **свойство железа**, из которого растёт гибкость |
| Software / Hardware словами | Hardware как универсальный цикл над примитивными шагами |

**Главная мысль:** гибкость выиграла у «интеллекта» на уровне железа: машина стала мощной, потому что стала буквальной и переиспользуемой.

**Эмоция:** «А, поэтому один телефон и калькулятор, и плеер, и банк.»

**Результат главы:** перестать думать «компьютер иногда глючит / иногда умный» → «он исполняет ровно сказанное; странности — дырки в инструкции или состоянии».

## Секции — контракт (сжатый черновик)

### Интуиция

**Крючок (утвердить):** один ящик — утром калькулятор, днём печатная машинка, вечером плеер. Железо то же; меняется инструкция.

**Удар:** компьютер не «знает» математику и не «слышит» музыку. Он исполняет точно записанные шаги. Смена профессии = смена **программы**.

**Голос:** `ты`. Не пересказывать гл. 0 — одна отсылка: «в главе 0 помощник был метафорой; здесь — почему железо такое».

### История

≤ ½–1 экран.

- Было: машина «зашита» под одну задачу (переделка железа = другая задача).  
- Стало: исполнять **записанные** шаги → одна машина, много задач.  
- Имя «фон Нейман» / Паскаль / Бэббидж — максимум одна фраза + Glossary; не timeline.

**Не раздувать** «почему инженерия не строила понимающую машину» в второй why — один абзац максимум: сначала нужна была надёжная буквальность и гибкость; «понимание» — другой слой (позже / AI этаж).

### Как это работает

Один занудный цикл:

```text
Fetch → Decode → Execute → следующая инструкция
```

Инструкции примитивны («положи», «сложи», «сравни и прыгни»).  
Сложный UI / лента = огромная цепочка таких шагов. **Ум приложения = ум инженера в структуре шагов.**

Без ISA-таблиц. Без ассемблерного листинга.

### Внутри (L3, короткий мост)

Транзистор надёжно различает **два** состояния → всё исполнение в итоге опирается на это.  
CPU не знает «пользователь» / «корзина» — только паттерны битов и таблица операций. Значение — в голове инженера и в структуре программы.

**Стоп-линия:** не объяснять кодирование чисел, байты, endianness — это гл. Binary.

### Пример

Primary: человек («как обычно») vs машина (нужны канал / значение).  
Swift `isReady` / `nil` — **optional** (Approve): либо одна строка «тот же паттерн в коде увидишь позже», либо убрать из v1.

### Production

Три класса как **дырки в инструкции/состоянии**, не «баг процессора»:

- Race — порядок не зафиксирован  
- Force unwrap — сказано распаковать  
- Off-by-one — граница не однозначна  

Вывод унести: «странно себя ведёт» → сначала *где неоднозначность*, не *что с CPU*.

### Интервью

| Вопрос (для тебя) | Суть ответа |
|-------------------|-------------|
| Почему «глупый», но быстрее человека в счёте? | Мощность ≠ понимание смысла |
| Почему один компьютер — и калькулятор, и плеер? | Программа = сменная инструкция |
| Почему два состояния, не десять? | Надёжность различения сигнала → мост к Binary |
| «Само крашнулось» — как ответить? | Не винить железо; искать дырку в инструкции/состоянии |

Типичная ошибка: «он иногда глючит» вместо «исполнил сказанное, включая непредвиденное».

### Лабораторная

10 мин, без кода: один реальный баг (краш / кривой UI) → расписать «где человек оставил дырку», не «что сломалось в системе».  
Позже: одна заготовка → `notes/Interview-Pack.md`.

### Конспект (без ссылок)

Черновик сжатия:

> Компьютер — универсальная машина: не понимает задачу, а исполняет точные инструкции; смена задачи — смена программы. Буквальность на железе дала гибкость лучше, чем «умная» машина под одну профессию. Физика тянет к двум состояниям — поэтому дальше нужны Binary и перевод текста программ в форму для цикла Fetch-Decode-Execute. Странности в проде чаще всего — неоднозначность инструкции или состояния, а не «злой» процессор.
